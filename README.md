# OthelloConsole

C#(.NET 10)で作ったオセロです。
AIは、ビットボード + NegaScout + 置換表 + 終盤の完全読みで探索し、約3,000万局面から学習したパターン評価で盤面を評価します。強さはレベル1〜15から選べます。
**Avalonia UIのウィンドウ版(GUI版)** と、**コンソール版** の2通りで動きます。

この作品は勉強の一環で作成したものです。2026年11月に、学校の出し物で展示しました(GUI版で来場者とCPU対戦)。

## 1. 動作環境・ビルド方法

| 項目 | 要件 |
|------|------|
| ランタイム | .NET 10 |
| OS | Windows / macOS(Linuxは未確認) |
| UIフレームワーク | Avalonia UI 11.2 |
| MVVM | CommunityToolkit.Mvvm 8.4 |

コマンドは `OthelloConsole/`(`.csproj` のあるフォルダ)で実行します。

```bash
# ビルド
dotnet build -c Release

# GUI版で起動(引数なし)
dotnet run -c Release

# コンソール版で起動
dotnet run -c Release -- --console

# コンソール版 + デバッグログ
dotnet run -c Release -- --console --debug
```

AIは重い計算をするので、`-c Release` で動かしてください(Debugだと思考時間が大きく延びます)。

### Windows用の配布物

```bash
dotnet publish OthelloConsole.csproj -c Release -r win-x64 --self-contained -o ../publish/win-x64
```

`publish/win-x64/` に、.NETを入れていないPCでも動くexeができます。評価ファイル(`weights/pattern_eval.bin` 約18MB、`weights/move_ordering.bin` 約7MB)も一緒に入ります。exeと `weights/` は同じフォルダに置いたまま使ってください。

## 2. 遊び方

### 先手はいつも黒

どのモードでも、対局は黒から始まります。人間が後攻を選ぶと、AIが黒で先に打ち、人間は白になります。

### GUI版(引数なし)

右側のパネルで設定し、「ゲーム開始」を押すと対局が始まります。

| 項目 | 内容 |
|------|------|
| モード | AI対戦 / 2人対戦 / AI対AI |
| あなたの手番 | AI対戦のときだけ。先攻(黒)/ 後攻(白) |
| AI レベル | AIが打つモードのときだけ。レベル1〜15(最初はレベル6) |
| ゲーム開始 | 対局を始める。対局の途中で押すと、最初からやり直す(AIが考えている間は押せない) |
| AIの戦績 | AI対戦の勝・負・分を、AIから見て表示する |
| この試合をカウントしない | 直前の1局を戦績から取り消す |

盤面では、置けるマスに小さな印が出て、直前に打たれたマスの色が変わります。マスをクリックすると石を置きます。
AIは打つ手を決めたあと0.6秒、パスのときは1.5秒待ってから次に進みます(見ている人が追えるようにするため)。

### コンソール版(`--console`)

コンソール版は、動作を確かめるためのものです。AIの手のあとに待ちはありません。

```
1. モード選択: AI対戦(1) 2人対戦(2) AI対AI(3)
2. [AI対戦のみ] 先行(1) / 後攻(2)
3. [AIが打つモードのみ] AIのレベルを入力(1〜15。範囲外や数字でないときはレベル6)
4. Enterで開始("debug" と入力するとデバッグモード)
```

| 入力 | 動作 |
|------|------|
| `34` | 縦3番・横4番に石を置く |
| `3 4` や `3,4` | スペース・カンマ区切りでも置ける |
| `end` | 対局をやめて終わる |

盤面は `●`(黒)・`○`(白)・`#`(置けるマス)・`-`(空き)で表示します。

## 3. AIのレベル

レベルNのAIは、Egaroucid(後述)のlv.1〜10と同じ決まりで読みます。

- **中盤**: N手先まで読む
- **終盤**: 残りのマスが 2N 以下になったら、最後まで読み切る(完全読み)。ただし上限は残り20マス
- **レベル12以上**: 中盤でMPC(浅い読みから深い読みの結果を見込んで枝を切る近似)を使う。レベル11までは近似なし

| レベル | 中盤で読む手数 | 完全読みを始める残りマス | MPC |
|:---:|:---:|:---:|:---:|
| 1 | 1 | 2 | なし |
| 3 | 3 | 6 | なし |
| 5 | 5 | 10 | なし |
| 6(最初の値) | 6 | 12 | なし |
| 8 | 8 | 16 | なし |
| 10 | 10 | 20 | なし |
| 11 | 11 | 20 | なし |
| 12 | 12 | 20 | あり |
| 15 | 15 | 20 | あり |

探索は途中で打ち切らず、決めた深さを最後まで読みます。そのうえで、どのレベルでも1手が10秒以内に終わることを目標にしています。

### 強さの目安(Egaroucid lv.5と対戦、序盤8手をランダムにして先手・後手を入れ替え)

| 自分のAI | 局数 | 勝率 |
|---|---:|---:|
| レベル15 | 100 | 90.5%(90勝9敗1分) |
| レベル5 | 200 | 50.2% |

レベル15の100局では、1手の思考時間は平均0.2秒・最大5.5秒でした(Apple SiliconのMacで測定)。

## 4. 棋譜と戦績

棋譜と戦績は、exeと同じフォルダの `data/` に保存します(起動したフォルダには左右されません)。

| ファイル | 書くタイミング | 内容 |
|---|---|---|
| `data/game_records.jsonl` | GUI版で対局が終わる(または途中でやめる)たび | 1局1行のJSON。日時・モード・AIのレベル・人間の色・結果・石数・評価ファイル・各手(色・人間かAIか・パス・表記・AIの思考時間)・f5d6形式の手順 |
| `data/game_records.txt` | 最後まで打った局(GUI版・コンソール版とも) | 1局1行のf5d6形式 |
| `data/battle_records.json` | GUI版のAI対戦が終わるたび | 勝・負・分(来場者から見た数。画面ではAIから見て表示する) |

### f5d6形式

黒が先手の対局を、パスを書かずに、手の表記(列の英字の小文字 + 行の数字)だけで並べた1行です。

```
f5d6c3d3c4f4f6f3e6e7...
```

Egaroucidの `play` コマンドと同じ書き方なので、そのまま読み込ませて検討できます。

## 5. AIの作り

`OthelloAI` が探索を、`PatternEvaluator` が評価を受け持ちます。盤面は、AIの中では64ビットの整数2つ(手番の側の石・相手の石)のビットボードで持ちます。

### 中盤の探索

- **反復深化 + NegaScout**: 深さ1から決めた深さまで読み直し、浅い読みの結果を、深い読みの手の並べ替えに使う。
- **置換表**: 約800万件(2²³)。同じ局面を2度読まないようにする。約400万件では、局面によって1手に10秒近くかかったため増やした。
- **手の並べ替え**: 置換表の手 → Killer Move → History。深さ4以上の節点では、置換表の手の後ろを「並べ替え用の軽い評価 + 相手の打てる手の数 × 64」の小さい順に並べる。
- **MPC(Multi-ProbCut)**: レベル12以上で使う。深さ3以上の節点で、浅い読みの値が「β + 余裕」以上ならβ、「α − 余裕」以下ならαを返して枝を切る。余裕は、実戦の局面572個で測った「深い読み − 浅い読み」の誤差の標準偏差 × 2.5(`MpcError.cs`)。
- 以前はLMR(後ろの手を浅く読む近似)を使っていましたが、見落としで弱くなっていた(レベル5対lv.5の400局で、LMRあり33.0%・なし45.1%)ためやめました。

### 完全読み(終盤)

- 置換表・ETC・手の並べ替えつきのNegaScout。並べ替えは、相手の打てる手が少ない手から。残り12マス以上は評価関数も使い、残り16マス以上は2手読みの値で並べる。
- 残り6マス以下は、置換表と並べ替えを使わない小さな探索(偶数理論で、空きが奇数の区画を先に打つ)。
- **終局の値**: 空きマスが残って終わったときは、空きマスを勝った側に数えて石数の差を出す。石数の差が同じ手どうしでは、勝つときは早く終わる手、負けるときは長引かせる手を選ぶ。相手の石を全部取れる局面では、いちばん早く全部取る手を選ぶ。

### 差分評価

探索では、評価に使う64か所のパターンの番号を局面と一緒に持ち歩き、打った石と裏返した石の分だけ足し引きします(`EvalState`。`Vector128<ushort>` × 8本で更新)。盤面から毎回数え直すより、中盤の探索が約1.9倍速くなりました。

## 6. 評価関数(パターン評価)

盤面の部分(パターン)ごとの石の並びに点数をつけ、その合計を「手番の側から見た最終の石数の差の見込み」とします。

- **パターン**: 16種類(辺・角の周り・2〜4列目・斜めなど)。盤の回転・反転で写した4か所ずつに置き、1局面で64か所を見る。回転・反転して同じになる並びは同じ点数にまとめるので、盤を回しても評価値は変わらない。
- **段階**: 打った手の数で15段階(4手ごと)に分け、段階ごとに別の点数表を持つ。
- **学習**: 約3,000万局面(下の表)を、目標の値との差が小さくなるように確率的勾配降下法で30周学習した。検証用の局面での誤差は平均5.94石。
- **ファイル**: `weights/pattern_eval.bin`(独自のバイナリ、約18MB)。作った日時・使ったデータ・誤差は隣の `pattern_eval.meta.json` にある。

| 学習に使った局面 | 数 | 目標の値 |
|---|---:|---|
| Egaroucidの教師データ | 約2,500万 | Egaroucidの評価値 |
| WTHOR(大会の棋譜) | 約515万 | 残り24マスからの理論値 |
| 展示の棋譜 | 約7,800 | 最終の石数の差 |

### 並べ替え用の軽い評価

16種類のうち4種類(パターン9・10・12・15)だけで点数を引く、手の並べ替え専用の評価です(`weights/move_ordering.bin`、約7MB)。中盤の深さ4以上の節点だけで使います。完全読みでは、64か所の評価で並べるより読む局面が増えたため使いません。

## 7. 開発用のコマンド

`OthelloConsole/` で `dotnet run -c Release -- <コマンド>` のように実行します。
Egaroucid・教師データ・WTHORは、リポジトリの `external/` に置きます(gitの対象外。下の「出典」を参照)。結果は `bench-results/` に残ります(gitの対象外)。

| コマンド | 内容 |
|---|---|
| `--bench --our-level <N> --level <Egaroucidのレベル> --games <局数>` | Egaroucidと対戦する。序盤をランダムに打った局面で、先手・後手を入れ替えて2局ずつ打つ。勝率・石数の差・1手の思考時間(平均・最大・10秒を超えた手の数)を出す。`--opening-moves 8`・`--seed 1`・`--threads 1`・`--book`・`--out <出力先>` |
| `--search-check [--positions 200]` | 探索の確認。ランダムな局面で、AIの手と単純な探索の最善手を比べる(終盤の完全読み・中盤2段階・相手の石を全部取れる局面)。探索を変えたら、すべて `[OK]` になることを確かめる |
| `--endgame-bench` | 完全読みの思考時間を測る。`--wthor <wtb>`・`--empties 16,18,20`・`--positions 30`・`--level 15`・`--force-solve`。`--transcript <f5d6の手順>`・`--only-move <何手目>` で、棋譜1局分の各手も測れる |
| `--mpc-stats` | MPCの誤差を集める。`--wthor <wtb>`・`--empties 20,24,…,56`・`--positions 60`・`--max-depth 14`・`--threads 8`・`--out <csv>`。評価関数を替えたら、これで `MpcError.cs` を作り直す |
| `--pattern-check [--positions 2000]` | パターン評価の確認(回転・反転で値が変わらないこと、評価ファイルの読み書き、差分評価の一致) |
| `--analyze <棋譜(.jsonl / .txt)>` | 棋譜の各手をEgaroucidで評価し、最善手からの損と「今のAIならどの手か」を出す。`--index <何局目>`・`--level 18`・`--our-level <N>`・`--threads 1` |
| `--convert-records <JSONL> [--out <txt>]` | JSONLの棋譜をf5d6形式に変換する(最後まで打った局だけ。白が先手の古い局は、色を入れ替えて左右反転し、黒が先手に直す) |
| `--train-pattern` | パターン評価を学習する。`--egaroucid <zip/フォルダ/txt>`・`--wthor <フォルダ/wtb>`・`--records <jsonl/txt>`・`--epochs 30`・`--learning-rate 0.002`・`--limit <局面の数>`・`--out weights/pattern_eval.bin`。`--patterns 9,10,12,15` を付けると並べ替え用の評価を作る |

共通のオプション:

| オプション | 内容 |
|---|---|
| `--weights <パス>` | 評価ファイルを替える(標準は `weights/pattern_eval.bin`) |
| `--mpc` / `--no-mpc` / `--mpc-t <倍率>` | MPCをレベルに関わらず使う / 使わない / 余裕の倍率を変える |
| `--ordering <パス>` / `--no-ordering` / `--ord-mid-depth <深さ>` / `--ord-mobility <重み>` | 中盤の並べ替え用の評価を替える / 使わない / 使い始める深さ(標準4)/ 相手の手の数の重み(標準64) |
| `--verify-eval` | 評価のたびに、差分評価の値を盤面から作り直した値と比べる(とても遅い) |

例:

```bash
# レベル15対Egaroucid lv.5を100局
dotnet run -c Release -- --bench --our-level 15 --level 5 --games 100

# 展示の棋譜で、人間が勝った局を分析する
dotnet run -c Release -- --analyze Data/collected/game_records.jsonl
```

ベンチを並べて動かすと、思考時間が長く出ます。思考時間は1つだけで動かして測ってください。

## 8. ログ

`OthelloDebugLog` が、コンソール版のログを書きます。ログは、起動したフォルダの `Log/` にできます。

```
Log/
└── 2026-11-16_14-30-00/       # 対局を始めた日時
    ├── Gamelog.txt            # 設定・各手・盤面・AIの読みの統計(いつも書く)
    └── AILog/
        └── AILog-<手数>.txt   # 各手のAIの思考ログ(デバッグモードのときだけ)
```

| レベル | 出る条件 | 内容の例 |
|---|---|---|
| `Info` | いつも(コンソール) | 読んだ深さ・局面の数・最善手・思考時間 |
| `Debug` | `--debug` で起動したとき、または開始前に `debug` と入力したとき | 反復深化の各深さの結果・完全読みの結果・置換表の統計 |
